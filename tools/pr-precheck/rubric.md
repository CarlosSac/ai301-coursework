# Rubric: is this pull request ready to submit?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| diff-matches-plan | Every changed file and hunk in the diff, read against the plan's scope (in-scope and not-in-scope lines, files, approach) and its deviation notes; then every in-scope item of the plan, read back against the diff. | Pass if every hunk carries out a step the plan names or a deviation note records, AND every in-scope item of the plan appears in the diff or its omission is recorded in the plan's notes and restated in the description. Tests for the fix, and changelog or docs entries the repo's stated standards ask for, count as in scope. Fail if the diff adds anything the plan does not name (a new option, flag, setting, rename pass, rewrite, or refactor), touches a file or behavior the plan scopes out, or leaves out a planned item with no note, or if the diff never implements the plan's fix at all. | required |
| description-matches-diff | Each claim the PR title and description make about the change (what it does, which files or docs it updates, "implements the plan exactly", "no changes beyond", "no functional changes outside"), read against the diff. | Pass if every claim is true of the diff. Fail if the description claims something the diff does not deliver (a docs update, a test, a behavior) or claims fidelity or narrowness the diff contradicts, even when the code change itself is good. | required |
| evidence-decisive | The test evidence (and any before/after in the description), read against the plan's test plan and the repro steps it re-runs. | Pass if the plan's own repro is re-run on the changed code path and shows observable output for the after (the command and what it printed or did), with the before either shown or quoted from the repro, AND every other failure mode the test plan names is mentioned with its result or explicitly disclosed as not run. Controls and secondary scenarios pass when their result is stated in a line ("control unchanged", "prints the warning"); only the plan's main repro needs pasted output. Fail if the main repro's after is a claim without output ("tested locally", "works now", "verified on my machine"), if the evidence only exercises a path the fix does not change (a control instead of the repro, a different request shape), or if it never mentions a failure mode the test plan names. | required |
| repo-checks-reported | The test evidence and description, read against the repo's stated test or check requirements (PR template checklist, contributing guide's test command, "the test suite passes"). | Pass if the PR reports the outcome of the repo's own suite or required checks by naming what ran and its result, or reports a failing check honestly with its reason. Also pass if the repo's stated standards name no suite or checks to run. Fail if the repo asks for its suite or checks to pass and the PR shows no outcome for them. | required |
| diff-clean | Every hunk of the diff and the commit list. | Pass if every added or removed line is part of the change: the fix, its tests, and the entries the repo asks for. Fail if the diff carries debris: debug prints or logging left in, commented-out code or earlier attempts, dead code (unused functions, `allow(dead_code)`, `_unused` names), new TODO or FIXME notes, re-indentation, reordered imports, duplicated or re-printed identical lines, or whitespace churn on lines the fix does not otherwise change. | required |
| template-asks-met | The repo facts' PR template sections and checklist items and the contributing guide's explicit PR asks (issue link line, changelog or whatsnew entry, tests added, required sections), read against the description and the diff. | Pass if every section the template asks for has real content and every item the template or guide states as required is present in the description or the diff, or its absence is explained. Also pass if the repo has no template and its guide states no specific PR ask. Fail if a stated ask is visibly unmet: a required section or checklist left out, a required `closes #` or `fixes #` line missing, or a required changelog or whatsnew entry absent from the diff. | required |
| ai-policy-honored | The repo facts' contribution policy (live: `docs/CONTRIBUTING.md` plus the course's disclosure rule), read against the description, treating every PR as AI-assisted work. | If the policy requires disclosing AI use (the tool or the extent), pass only if the description contains that disclosure. If the policy only asks that text be the contributor's own words, pass when the description is specific to this change rather than generic. If no AI policy is stated, pass. | required |
| commits-descriptive | The commit list. | Pass if each commit message says what that commit changes. Fail on messages like "wip", "fix", "misc cleanups", or "fmt". | preferred |

## Verdict rule

Accept only if every required check passes. Preferred checks never change the verdict. An `unclear` grade on a required check counts as fail, because a PR that cannot be verified from the package is not ready to submit. A shortfall the plan's notes record and the description restates is not a fail on any check; a shortfall only one of them mentions, or neither, is.
